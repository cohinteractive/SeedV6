# R001 — common-search fixed-work baseline

Prospective 29 October 2026. Question: what is CP64's development performance
relative to frozen Gen32 with search flags and node budgets held equal, and is
the chosen node mechanism exact/reproducible on the actual runtime?

No learning or final confirmation. Reuse eight explicitly consumed conventional
NNUE development openings (openings-screen.json), both colors,16 games fixed in
advance,10,000 admitted child nodes/move including qsearch. One game/search at a
time; one worker,16MiB TT/engine,384MiB heap/engine,one active JVM logical processor,
BelowNormal,SCReLU vector backend,Construction V1 flags262143/ADAPTIVE16 both.
No book/tablebases/ponder or chess clocks. Maximum640 played plies after opening;
caps censored, never draws.30-second per-request watchdog is a failure detector,
not a time control; failed requests never receive time-forfeit game scores.

Before games: independently replay legal PVs and best moves; four positions
(start,castling,en-passant,promotion),budgets1/100/10,000,two newgame repeats,
both models. Require final whole-request receipts,exact exhaustion and identical
move/completed-depth information excluding timings. Targeted core model tests
cover accumulator/full rebuild,special moves,null/siblings,overflow and qsearch.
The explicit research launcher uses the same production search implementation
with a common configuration; no production default or Search canon changes.

Record hashes of source,models,plan,runner,frozen compiled runtime and transcripts.
Fresh run directories; resume validates frozen binding,legally replays completed
game receipts,skips them,restarts only the interrupted game. Run through existing
Windows owned-job supervisor; graceful quit/forced owned-job cleanup on failure.
Resource samples before launch,each game and32 plies; no availability retries.
Expected <=1GiB working memory,one CPU search,~1..5 minutes for this shallow stage;
measure actual cost before scaling. Non-checkpointed preflight <5 minutes; each
completed game atomic. The temporary raw runtime is immutable for this protocol.

Analyze opening-pair bootstrap95% and conservative bounded-pair Hoeffding95%,
W/D/L,caps and full-allocation adverse bounds. Development only,too few clusters
for decisive strength/Elo. Never extend for significance or tune on final data.
Regardless of result, diagnose scale/training before architecture-only attribution.
R002's low-cost matched-target learning diagnostic is admissible after technical
qualification; larger matches require a new question and fresh prospective plan.

Execution commands use baseline.py preflight/match with r001-plan.json; exact
invocations,results and resume boundary are appended after execution.
