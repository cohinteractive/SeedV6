## Finding and decision

**Confirmed training-semantic/calibration defect, with an objective/search
mismatch as its mechanism.** The E012 trainer correctly optimized its written
formula, but that formula calibrated an outcome to the entire +/-32511 search
range while valuing a pawn at 100 in the fixed prior. Learning consequently
overwhelmed useful material. This is not evidence that NNUE intrinsically cannot
learn. No evidence implicated an Adam implementation error, inverted labels,
double-counted material, a different Arena evaluator, or serialization damage.

The repair changes supervision to cross entropy through the existing WDL link
on the **actual total score in pawns**. Initialization, material, architecture,
search mapping, LR, optimizer, batch and epochs remain unchanged. New material
lineages use a separately persisted v2 objective; old models/campaigns retain
their original identity and remain reproducible. No historical store was edited.

The catastrophic failure disappears in the tested repaired runs, including the
actual 131072-position, eight-epoch intensity. This is **not trained parity
acceptance**: the unchanged-gain full run scored only 36.72% over 64 depth-4
games against Gen0 despite improved held-out objective metrics. A diagnostic
quarter-gain control scored 60.94% on the same openings without retraining.
Residual amplitude/search compatibility is therefore a concrete remaining
research issue. The quarter gain is **not promoted**: it was tested on one
trained full-intensity model, not on a prospectively reset multi-initialization
Gen0/trained comparison. No architectural superiority/limitation is established.

## End-to-end semantic audit

1. `SequentialTraining`, `SourceLedger`, `DataSources` and `SourceReaders`
   select/pin source ranges. The generation uses equal source weights, no
   generated self-play positions, and game-pair rather than held-out selection.
   `CorpusTraining.Examples` retains targets by sample identity; its draw
   placeholder cannot replace the explicit corpus target selector. CP is
   transformed once for Black STM; signed mate maps to +/-1. BT4 reconstructs
   Q directly from its encoded score, without the BRN2 CP/32511 adapter.
2. `NnueMaterialBootstrap` is exactly STM material P100/N320/B330/R500/Q900/K0.
   It is fixed, outside learned parameters, refreshed/incremented identically
   in search. Supervision's separate material inventory P1/N3/B3/R5/Q9/K0
   parameterizes the pre-existing WDL link; it is not another search prior.
3. HalfKP has two 64-unit accumulators, STM-first concatenation, a 32-unit
   hidden layer and scalar output. Both hidden stages use clipped ReLU [0,1];
   output is tanh. All 3149953 parameters retain the same initialization: seeded
   SplittableRandom uniform weights in [-1/64,1/64), zero biases. Gradients
   use the shared forward values and zero clip derivative at boundaries.
4. E012 v1 predicts `s=clip(tanh(raw)+M/32511,-1,1)` and minimizes
   `.5*(s-y)^2`. It does include material in training: **no missing subtraction
   or double count was found**. Its residual is `y-M/32511` in outcome units,
   not a residual in material/pawn units. Search computes
   `clip(M+V1.map(tanh(raw)), +/-32511)`; minimum-nonzero rounding belongs only
   to search. These paths agree within at most one search unit.
5. Batch gradients are reset, accumulated over the intended samples and averaged
   exactly once. Conventional Adam uses float32 parameters/gradients/moments,
   double update arithmetic, LR .001, beta1 .9, beta2 .999, epsilon 1e-8;
   bias correction derives from the persisted step. Previously active sparse
   moment rows still decay/update when absent. No schedule, clipping, weight
   decay or normalization was found. Invalid updates are checked before
   publication. BRN3's masked/double optimizer is different and unchanged.
6. There are 1024 batches/epoch and 8192 steps/generation at 131072x8, batch128.
   `SelfPlayTraining` shuffles afresh each epoch using a deterministic
   SplittableRandom sequence. The full repaired run uses the actual ordinary
   seed1/generation1 shuffle seed `-6540313355536843707`. GenN+1 resumes GenN
   latest-training weights and moments, even when GenN did not become Best.
   This explains how rejected Gen1 can seed the observed Gen2; it is not a
   stale optimizer bug.
7. Model and optimizer codecs retain exact float bits plus checksums. There is
   no quantization/conversion of trained weights on publication; only final
   search score rounding. Immutable/checksummed checkpoint publication and
   cursor resume preserve lineage. Actual original Gen0/1/2 optimizer snapshots
   reproduce their published network bytes exactly. Historical prepublication
   scratch was not recorded; controlled reruns and current snapshot equivalence
   establish that no publication/reload transformation explains the collapse.
8. Production, full-refresh, scalar oracle, CGLHW and Arena construction agree.
   The actual Arena Gen0/Gen1 checkpoint audit also verifies model/optimizer
   identity and train/search agreement. Its diagnostic residual RMS grows from
   2.40 to 14754 units. These probe positions are **not asserted held out from
   that separate Arena**. The integration test additionally exercises every
   legal child of fixed audit positions before/after training and reload.

The concrete calibration contradiction: at material inventory78, CP100 has
target .499. A zero-residual one-pawn material advantage predicts only
`100/32511=.003076` under v1. Fitting .499 demands a total score near
16223 units, about 162 pawns, despite that prior. The gradient is doing what
the formula requests; lowering LR only delays that destination.

## Repair and checkpoint contract

Let `s=clip(tanh(raw)+M/32511,-1,1)` and `p=325.11*s` (pawns).
Use the existing `Brn3Objective` supervision-only smooth WDL function `f(p)`.
The binary expected-score probability is `(1+f(p))/2`; target probability is
`(1+y)/2`. Optimize its cross entropy, with raw derivative
`CE'(p)*325.11*(1-tanh(raw)^2)` inside the score clamp and zero outside.
Material is included **once**, before the link; no inverse-WDL target is
required, including at +/-1. Finite differences cover all parameter groups
and both STM orientations. A zero residual on the controlled one-pawn case
already explains the material-derived target instead of learning it again.

No BRN3 runtime/features/optimizer changed. Its existing CE/WDL link supplies
supervision only; this adds no handcrafted evaluation knowledge or privileged
data to NNUE. E013 does not use BRN3's .25 search gain in production, nor does
it adopt E009's zero head, pawn-output head or double masked Adam.

New identity: `seedv6.nnue.material-additive.pawn-wdl-ce.adam.v2`.
Model/optimizer magic: `S6NMAT02` / `S6TMAT02`; same geometry and payload size.
Historical `01` payloads round-trip and resume v1 exactly. A model/optimizer
objective mismatch is rejected; held-out comparison between unlike recipes
is rejected. New Training, Arena and `nnueCorpusTrain --variant=material`
initializers use v2. Arena persists its objective binding; old JSON with the
field absent preserves the historical binding and v1 resume. An exact selected
model copy inherits the source recipe rather than silently relabelling moments.

`SelfPlayTraining` initial/final/mean training losses now respect persisted
objective semantics (CE for v2); held-out selection remains half-MSE of the
correct linked outcome. These are distinct metrics. The runtime evaluator is
unchanged and Gen0 scores are exactly E008's. An existing running binary and
old v1 lineage are not automatically repaired by source edits: a subsequent
corrected campaign must use the rebuilt code and a fresh same-seed material
Gen0 fork, preserving the historical lineage as evidence.

Early private CE trials used a temporary helper and historical headers only in
isolated `app/build` outputs. They were never published into a store. The
production v2 pilot reproduces their numeric model/optimizer payloads exactly
(excluding header/checksum); see [repeat-equivalence.json](e013-training/repeat-equivalence.json).
The retained harness writes only the properly versioned production objective.
