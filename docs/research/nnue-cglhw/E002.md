# E002 — shared representations and geometric factors

> Historical Track A: knowledge-free NNUE versus material-bootstrapped BRN-3.
> Preserved as architectural-control evidence by the 2026-10-05 fairness amendment;
> rejection statements here do not apply to the new bootstrap-parity Track B.

Registered 2026-10-05, after E001 outcomes and before E002 measurements.

E001 shows perspective consistency alone is insufficient. Baseline king-index
changes and reflection remain poorly correlated. Test four different sharing
structures with the antisymmetric neural head, all zero-centred random weights:

- `piece-square`: 12 relative piece identities x 64 squares -> shared 64-wide
  accumulators. Removes king context; king moves now update only changed pieces.
- `smooth`: per-piece-identity learned constant, rank coefficient and file
  coefficient. Fold these raw geometric factors into 768 embedding rows. Nearby
  squares share most of their representation; no preferred rank/file is specified.
- `mirror-smooth`: same, but file coordinate is distance from the nearest edge,
  tying horizontal reflections. This ignores castling-right evaluation as the
  original NNUE does; only no-castling positions support a formal symmetry claim.
- `counts`: learned embeddings of raw relative piece counts, with no square
  information. Counts are facts; their learned values remain random and signed.
  Aggregate cancelling deltas before float updates so quiet moves are bit-stable.

All use two 64-wide incremental sums and a shared 128 -> 32 -> 1 clipped head,
antisymmetrized as in E001. Independent weights use uniform +/-1/64; smooth's
three factors each divide by sqrt(3). No material/PSQT, positive-sign selection,
seed selection, labels or training. Independent parameter counts: piece-square
53,280; smooth/mirror 6,432; counts 4,896. Smooth folded inference payloads are
53,280 floats, counts 4,896. Both kings are factual piece inputs with no values.

External concept check: [official Stockfish NNUE documentation](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/nnue.html)
explains sparse feature sharing and folding redundant factors into inference
weights. [Feature initialization documentation](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/features.html)
describes zero-initialized virtual factors, which by themselves do not change
Gen-0 geometry. Our deliberately random shared factors test a different question.
No implementation copied; SeedV6's interfaces, initializations and math remain
authoritative. Consulted 2026-10-05.

All full/incremental errors <=1.747e-10. Smooth representations do deliver the
predicted topology. Their current kernel cost is marginally **outside** the
frozen guardrail (about 2.03x current NNUE, versus maximum 2x, and roughly .67x
BRN). Do not call them cost-qualified. Counts narrowly fits historical costs,
subject to co-measured controls. Full refresh + head costs 3.44..3.48 us, preserving
an incremental advantage. Repeated clipping inside each hidden block is an
obvious possible mechanical optimization, deferred until strength merits effort.

Stage-2 mechanism screens now running, all four variants and all six seeds. The
three marginal cost failures remain explicitly mechanism-only, not contenders
unless both strength and a subsequently measured mechanical correction justify
continuation. This is one bounded strength screen, not expensive training.

**Numerical correction discovered while screening:** the original count-only
implementation summed identical embeddings once per occupied square. Opposite
perspective summation orders left roundoff at balanced counts (e.g. seed41001
starting position raw 2.91e-11), promoted by sign-preserving mapping to +1. This
is not legitimate learned preference. Count results from `e002-matches` are
therefore diagnostic only and are superseded for inference. No production code
is affected. Fix: exact 12-integer counts per state; refresh the learned sums in
fixed relative-channel order only when counts change. Quiet transitions preserve
the sum bits. Balanced counts now must evaluate exactly zero and transitions
must match full refresh exactly. The fix is not a material prior: all embedding
and readout weights remain unchanged, random and zero-centred. Add focused tests
and repeat count-only screening after the already-running old build completes.

Old-build screen completed: piece-square, smooth, mirror-smooth and old counts
each score **1 win / 0 draws / 95 losses**, no caps. The wins are different
seed/opening/colour combinations; none is representative architecture strength.
Reject the three spatial-sharing variants as contenders. Better topology did not
close the practical Gen-0 gap. Keep results as distinct negative mechanisms.

Fixed-count tests pass, including exact zero at balanced counts and exact full/

if strength merits continuation. Corrected count matches now running separately
