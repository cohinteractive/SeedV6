# E006 — Broader BT4 coverage after measured overfitting

Prospective plan, 2026-10-22. E005 demonstrated improvement over E003 in a small
same-search screen (11W/5D/0L), but remained below Gen32. Its held-out MSE worsened
from .021569 at checkpoint 16 to .023484 at 64 while training-sample MSE fell to
.007045. Additional constant-rate epochs on the same 8M sample are not selected.
Checkpoint 16 scored 5W/2D/9L against Gen32 versus 2W/5D/9L at 64. These are reused
development openings and uncertain small samples, not an independent Elo claim.

The next hypothesis is that broader training coverage will reduce this measured
generalization gap. Preserve architecture, teacher-only Q target, optimizer, batch,
and global decay recipe. Branch from E005 checkpoint 16 (the better diagnostic
checkpoint and better observed Gen32 screen), explicitly preserving later completed
checkpoints as negative evidence. This is an experimental data fork, not a claim
that E005 checkpoint 64 was lost or that a held operation resumes from an old point.

## Data plan

Run `PrepareBt4 e005-bt4-source.json raw/e006-data 1024 16 32768 20261022` through

Exact placement+STM dedup remains global, validation first. Prepared chunks and
original files remain read-only. Preserve provenance, distributed upstream packing
comparison, all-target verification, hashes and the sampling limitations from E005.
The raised extractor bound keeps every array and byte offset within signed int.

## Training and evaluation

Declare the data fork and retain E005 checkpoint 16's optimizer payloads. Begin at
global superbatch 17, batch 4096, 1024 batches/checkpoint, seed 20261022, LR .001
with gamma .5 after every 128 global superbatches. Initially stop at 64 to compare
the new holdout trend against the same-step E005 and the starting checkpoint.
Further stages through 128/256 depend on actual generalization and strength evidence.
Use safe controller-owned checkpoints; owner NORMAL has no expiry.

Require existing export/features/integer/GPU parity and real UCI checks before
strength testing, and measure runtime cost. Screen against frozen Gen32 and use
the same-search evaluator control if needed to explain results. Stronger independent
confirmation follows only a promising candidate; no production replacement yet.
If this direction fails, retain the evidence and select a justified next conventional
approach. Experiment stopping is not programme stopping.
