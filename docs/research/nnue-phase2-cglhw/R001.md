# R001 — bounded clock and worker robustness

Selected only after C001 completed and passed every predeclared gate: 179W /
204D / 129L, +34.04 Elo, paired bootstrap 95% +10.86..+56.82. All 512 games
are uncensored and independently audited. This follow-up tests whether the same
direct128 checkpoint64 evaluator has an obvious transfer problem at a longer
clock or with two workers. It does not replace, extend or pool with C001.

Preserve the exact candidate and WDL25 files from C001. No retraining, search
changes, scaling changes or production integration. Enable only one/two workers
in the isolated research launcher and explicit harness options. Existing default
one-worker commands and production code remain unchanged. Freeze runtime v5 and
all tool hashes before play; do not modify any frozen v4 artifacts or protocol.

Before games, check the actual trained candidate's incremental score against
independent full rebuild at every evaluation in bounded real two-worker searches.
Observe actual helper-thread evaluations, legal PVs, node-limit unwind, new-game
restart and drained workers. Verify final-runtime UCI lifecycle/configuration at
both worker counts for both models. Compare bounded v4/v5 one-worker outputs for
both models to guard against an unintended evaluator/search change.

Fixed follow-up conditions, in this order:

1. 64 games / 32 pairs, 400ms/move, one worker; first 32 reserved robustness roots.
   Budget 4800 observed match seconds, including interruptions and resume warmup.
2. 64 games / 32 pairs, 200ms/move, two workers; next 32 reserved robustness roots.
   Budget 2400 observed match seconds on the same accounting basis.

Total additional match allowance is 7200 seconds, as reserved in C001. The
remaining 64 robustness pairs stay unused; do not add games after seeing scores.
Both conditions use Hash32, CLV_C1, BOUNDARY2, Java21, Vector API, -Xbatch,
ActiveProcessorCount equal to worker count, the existing two 20k-node warmup
passes on 12 cost roots, and an 800-ply censor ceiling. Play one game at a time.
Formal chess endings and claimable draws determine results; no adjudication or
censored-result imputation. The distinct root slices must be legal, unique and
disjoint from earlier development/confirmation/cost/parity roots.

These are descriptive robustness endpoints, not two more primary significance
attempts. Audit all games and artifacts, report paired 95% intervals separately,
and never pool scores across conditions. No interim efficacy decisions or retests.
Both scheduled conditions run irrespective of the first score, unless a technical
failure invalidates dependent work or the owner controller stops it.

Decision: technical failure/censoring leaves that condition unverified. An entire
paired 95% interval below even is evidence of harm in that condition and blocks
a broad promotion recommendation. A negative point with an interval spanning
even leaves transfer uncertain. Nonnegative points without detected harm provide
limited supporting evidence, not proof of gains or noninferiority at these small
samples. Any wider uncertainty remains explicit. No result grants promotion,
deployment, Mac/BotLi access or owner acceptance.

Qualification allowance: at most 900 supervised seconds for targeted build/checks
before reassessment. No full engine regression suite. Preserve failed checks and
all raw output; final evidence must identify actual runtime/model/tool hashes.
