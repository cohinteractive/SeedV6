# D002 — input overlap within the broad mixture

Prospective supplemental data audit, selected while S001 runs; execute only after
timed games release the compute controller. D001 proves chunk separation, not
unique evaluator inputs. The coverage ablation also changes sample frequencies and
passes per record; it is not a factorial isolation of diversity from weighting.
Initialization seeds do not reshuffle the fixed DirectSequential data stream.

Bounded question: how many same-input fingerprints recur within each33M source and
across the50:50 broad mixture? Scan the frozen67M records once, verify their SHA256,
canonicalize native STM-relative placement under file mirroring, and sort63-bit
fingerprints with one source bit. Report multiplicities and how many additional
source records match original-source inputs. Labels, castling/history and clocks
are excluded because these NNUE representations do not use them.

This is a probabilistic fingerprint audit, not a collision-free uniqueness proof
or source-game separation. Collisions would overestimate overlap; report the
random-hash approximation explicitly. No training/validation file is modified,
deduplicated, relabelled or selected by the result. Stronger conclusions need
actual game/source identifiers, not this hash calculation.

Budget: one controlled scan/sort,<=2 CPU workers,<=2GiB Java heap,<=300s. First run
synthetic same/mirrored/distinct placement fixtures to check source accounting and
label-independent matches. Preserve failures and outputs under raw/d002-*; track
only the compact result/recipe. No concurrent timed game, training or benchmark.
