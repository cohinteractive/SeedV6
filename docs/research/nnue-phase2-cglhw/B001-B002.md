# Architecture feasibility protocols

Prospective, before architecture implementation/training. Existing production and
Phase 1 remain unchanged. Common control: A001 independent-seed conventional256,
broad data/WDL.25/early decay, with unchanged logit400 and8 material outputs.

## B001: small downstream nonlinear residual

Keep dual256 incremental sums and the direct material head. Add one shared16-unit
SCReLU dense layer over the512 activated accumulator values and an8-head residual
output. The direct path protects representational access to the simple model;
the downstream path tests additional interactions. Train jointly, with a zeroed
residual output initializer and ordinary initialized intermediate weights. All
quantization scales are explicit, independently verified; no evaluation-scale
or search adjustment. This is a SeedV6 experiment, not an external architecture
replica. The extra dense layer runs on every evaluation and may be too expensive.

## B002: stable local-file pawn pairs

Append an unordered pair vocabulary to existing king-bucketed features. Each pawn
identity is relative colour ×48 plus rank2..7 square; triangular pair index over96
identities gives4560 possible inputs. Activate only same/adjacent-file pairs.
Perspective flips rank/colour, and king-file mirroring matches the base inputs;
pair features have no further king bucket. Share the existing256 accumulators.
Zero-initialize additional feature weights; preserve base factorization. The
number of active pairs is bounded by120, with equal cardinality per perspective.

Non-pawn placement changes preserve pairs; pawn changes update changed pairs;
perspective king-context changes use full refresh. Test captures of pawns by
non-pawns, en passant, promotion and changes of mirror. More stable than attack
features does not mean free: measure pair enumeration, changed-feature additions,
refresh frequency, model footprint and allocation under representative legal walks.

## Stages and stopping rules

Implement separate experimental codec/loader/trainer and reuse the research search
lifecycle. Cross-language independent float/integer/feature and incremental/full
oracles precede games. First4-superbatch smoke, fixed64 endpoint after parity;
same broad data, seed2026111501, WDL.25/LR.001/drop32. Monitor convergence without
choosing checkpoints by small-match results. If64 is clearly training-limited,
predeclare one longer/adjusted training investigation before family rejection.

Before long matches compare warmed base/head/update/refresh costs and allocation,
12 fixed-root search throughput, plus microbenchmark cold repeats. A large cost
regression requires an economical optimization or credible measured search benefit
before expensive confirmation. Synthetic cost alone cannot reject learned capacity.
Initial budget<=1 native GPU-hour per family; all expensive work sequential under
owner control. A failed kernel or quantization check stops strength testing until
corrected. At most one initial model per family enters the common fixed paired
screen; extensions need a recorded hypothesis, independent endpoint and economics.

## B001 implementation revision after the first endpoint

Before any scored games: the corrected allocation-free deep16 kernel costs about
1.43us/update+head versus0.74us for production WDL25. It redundantly clips/squares
the same512 accumulator values for all17 dense rows. Test caching those activated
values once per evaluation, then applying all dense rows to that scratch buffer.
This changes no weights, quantization or score formula. It adds2048 scratch bytes
per deep accumulator (~0.50MiB per257-ply state); base/pawn models need no such
buffer. Accept the revision only with exact old/new/Python arithmetic, zero hot
allocation and measured cost improvement on the same workload. Retain the earlier
runtime and measurements. This is a cost correction, not another trained candidate
or a reason to reset statistical attempts. No games have yet been played.

## Mechanism references (read 2026-11-14)

[Stockfish architecture](https://github.com/official-stockfish/Stockfish/blob/master/src/nnue/nnue_architecture.h)
currently combines king/piece, threat and pawn-pair representations, nonlinear
downstream layers and many conditional stacks. This supports investigation of
mechanisms; its C++ performance and strength do not transfer to Java or SeedV6.
No Stockfish implementation or weights are imported (GPL reference only).

[Pawn-pair interface](https://github.com/official-stockfish/Stockfish/blob/master/src/nnue/features/pp_3wide.h)
documents a96-identity triangular vocabulary and explicit changed-pair maintenance.
The mathematical pair indexing here is independently specified and tested.

[Pinned Bullet multilayer example](https://github.com/jw1912/bullet/blob/579b78b37a694cacd6e9ede4706386c15c34837c/examples/progression/4_multi_layer.rs)
demonstrates sparse incremental inputs, trainable factorization, nonlinear layers
and output selection. It explicitly warns its saved layout is not fast inference
layout. Existing MIT pin/notice applies to the training dependency. Its hyperparameters
are illustrative, not locally established optimal training or empirical Elo evidence.

[BT4 dataset card](https://huggingface.co/datasets/xushawn/test80-bt4-relabel)
identifies ODbL and FEN-only Jan/Feb labels, unlike later history-fixed files.
Source use remains local under existing provenance; no bulk redistribution selected.
